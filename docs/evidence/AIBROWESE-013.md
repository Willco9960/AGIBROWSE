# AIBROWESE-013 native profile isolation

Status: source implementation and focused local checks; **exact-source clean Windows GUI CI required before acceptance**.

Human startup and its legacy Default data remain intact. Agent has a separate CEF context. The native menu creates/selects human profiles and opens the chosen profile in a separate native window; full IDs identify deletion confirmation. Opened profiles require host restart before deletion; built-in Human/Agent cannot be deleted. [ADR-005](../decisions/005-native-profile-isolation.md) explains these user-facing limits and their storage/security reasons.

The focused native suite checks exact paths/identities, zero permissions, protected built-ins, native confirmation and revocation, temporary deletion, sharing conflicts, durable retirement and restart exclusion, junction refusal, actual directory rename prevention, failed opening retries and exact profile-wide grant/ticket revocation. It touches only a fresh uniquely named temporary fixture. Local sandbox ancestry restrictions required running this core test in the normal user context. No CEF launcher was used.

Pinned CEF `ClCompile` uses warnings as errors. Local checks include scoped/IPC/tab/privacy native suites, PowerShell parsing, embedded C# compilation and Node syntax. Full local packaging, postbuild copying and GUI execution remain prohibited because the upstream launcher is quarantined. No launcher was downloaded, copied or executed; no protection setting changed. The local JSON receipt records final hashes and checks.

The clean workflow retains task011's twelve tab proofs, task012's nine navigation proofs and all security/privacy/fallback scenarios. It adds `tools/cef/test-profiles.ps1`, which launches a narrowly marked fresh storage root twice against one ephemeral loopback server. Closed stages1–6 prove three separate profiles and native creation selection; stages7–9 prove their values after full host restart. Exactly three real requests to one long-cacheable HTTP endpoint are required across all nine stages, independently checking HTTP cache rather than only CacheStorage. Each run requires three positively observed restricted low-integrity renderers, graceful shutdown, no orphans and no forced cleanup.

The native creation check clicks the drawn profile button after actual root/cursor checks, waits for `GUI_INMENUMODE`, exact menu owner and foreground root, and submits Home/Enter once through `SendInput`. The content-free menu-request event precedes Windows menu entry; actual native creation selection is separately required once. Direct menu callback execution cannot pass. Real geolocation requests must be denied in all profiles. Human-only restrictive notification settings must remain Human-only after reload and restart.

Diagnostics contain only closed stage1–9 and reason1–8: cookie, localStorage, CacheStorage, HTTP cache, permission, native context/input, profile identity, temporary deletion. No page data, cookie value, origin, profile path or native identity is added to the diagnostic channel. Fixture-only V8 queries do not expose public arbitrary JS/CDP or renderer authorization. Production agent transport remains zero-grant.

Unverified limits: actual engine/menu behavior awaits clean CI; the native deletion confirmation dialog is implemented but not automated; core restart is a new store object, not a formerly CEF-opened context; the GUI probe deletes only a newly created never-opened temporary profile. Retired files need manual recovery. Profile naming/import, cross-platform storage and task014 permission approval UI remain unsupported.
