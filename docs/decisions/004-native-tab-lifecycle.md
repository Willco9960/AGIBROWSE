# ADR-004: Host-owned tab identities and CEF Views ownership

Status: implementation proposal for task011; parent review and clean Windows GUI CI required.

Date: 2026-10-03.

The native host reserves at most64 tabs (pending plus live) and32 windows. Stable opaque tab/window handles are host-registry identities, not credentials or globally unique identifiers across host restarts. Native engine bindings never derive identity from page/client strings or a tab's current list position. Closing immediately removes exact-tab scope documents, leases, pending scope tickets and tab membership in existing grants. A canceled human beforeunload dialog restores human lifecycle access without reinstating that authority; native reapproval remains required.

CEF154's supported **Alloy runtime style** is selected for Views and windows so the host owns the native chrome and shared window layout. This uses the pinned modern Chrome bootstrap and unchanged Chromium sandbox; it does not select the removed historical Alloy bootstrap/runtime, disable the sandbox, or fork Chromium. Alloy's default DoClose would request closure of the shared top-level window. The host instead removes and releases only the closing BrowserView, allowing its child widget/browser to finish destruction; OnBeforeClose releases frame/provenance state. The window delegate holds its initial View only until attachment, allowing that initial tab to move or close while sibling tabs remain alive. Final native-window closure closes all associated browsers; final-tab Ctrl+W reserves a fresh blank tab first.

Native Ctrl+T/W/Tab creates/closes/switches tabs. Ctrl+Shift+PageUp/PageDown changes the actual native child View order. Ctrl+Shift+N moves the current View into a new native window with strong-reference retention during detach/attach, current engine/context checks and rollback before closing an empty source window. These shortcuts are native capabilities, not public agent operations or grants. Agent dispatch/keypress gates remain later tasks and must reject privileged shortcuts.

Popups reserve a native profile/opener identity before CEF creation, retain CEF's inherited request context and inherit no application grant. Creation reservations expire after10000ms with a250ms UI sweep; aborted popups, opener shutdown and final window shutdown cancel reservations. Late engine creation for a canceled/expired reservation is closed and cannot recover the old handle. Callback barrier exceptions deny closure/human cancellation until a successful retry; normal production barriers revoke native scope synchronously. Native lifecycle diagnostics use appended closed event kinds with no page strings. Fixture failure stage accepts only0–7, and native failure reason accepts only thirteen predefined branches; no arbitrary numeric payload, coordinate or OS error is accepted.

The fixture requires real CEF callback proofs for popup registration, native reorder/move, beforeunload cancellation and later acceptance, inactive/initial tab close, blank replacement and final native shutdown. Its deadline-expiry case deliberately reserves a native pending tab without starting CEF creation; it verifies the production sweep path rather than claiming an injected CEF creation failure occurred. Local compilation/core tests cannot certify Views detach/attach or close behavior; clean pinned Windows GUI evidence is required before acceptance.

For the Windows Views fixture, CEF154's documented CefWindow testing input routes through native Windows Aura UI controls. The fixture converts its actual BrowserView button point to DIP screen coordinates, retains the owning window across one UI task yield, then revalidates native tab/window/engine/context ownership and the cursor's root HWND before a single down/up. It still requires the page's trusted click and active user activation to call real window.open; this input is fixture-only and supplies no production agent capability. The external harness requires distinct matched browser IDs and correctly ordered proof observations, without assuming relative ordering of title and popup callbacks on separate engine channels.

Exported fields are closed booleans only. The existing comparison and failed result remain intact until exact-source CI establishes whether root normalization or cursor routing is the relevant cause.
