# ADR-005: Native profile identities and separate CEF storage

Status: task013 source implementation; exact-source clean Windows GUI acceptance pending.

Date: 2026-10-04.

Each host-owned profile has its own explicit `CefRequestContext::CreateContext(settings, nullptr)` and a distinct persistent cache path below the validated CEF root. Browser creation never uses the sharing overload or global context. New-tab and popup binding require the native profile/context registry's exact `IsSame` identity; new contexts also reject `IsSharingWith` existing profiles. Renderer/client strings cannot create profiles or select contexts. Popups retain their opener's context and receive no application grants.

The initial window remains `human` with existing `Default` data. The reserved `agent` context uses `Profiles/Agent`, and future agent operations must use this native default rather than the active human tab. Current production transport remains zero-grant and implements no engine observations/actions. Opening the Agent native window supplies no transport authority. Up to16 additional human profiles have cryptographically random `p-` IDs and persistent ownership markers.

The native profile menu creates/selects profiles by opening separate native windows, preserving existing windows. Full IDs identify user-profile menu entries and deletion confirmation. Built-in Human/Agent deletion is unavailable. A user profile whose context was opened or attempted this run cannot be deleted until restart, even after tabs close: CEF storage may outlive released references asynchronously. The menu explains that requirement. Task014 owns native site/certificate approval UI. This task denies media and permission prompts and proves restrictive content settings belong to their own contexts.

`ProfileStore` validates absolute local roots, rejects traversal/ADS/UNC/device aliases and reparse ancestors, and retains actual read-sharing directory pins that deny both write and delete sharing. Metadata-only handles do not block Windows directory rename; permitting write-sharing could allow junction mutation without rename. Unopened user profiles have deletion-capable pins; opening retains an intermediate identity handle while installing a read pin and comparing volume/file identity. Failed validation permanently rejects retries. CEF compatibility of these restrictive directory pins requires actual CI. Discovery is bounded to128 entries and16 user profiles. Deletion targets only `Profiles/<exact ID>`, never Default, Agent, the root or Transport, and requires native confirmation and synchronous profile-wide scope revocation.

Deletion flushes a retirement marker before cleanup and opens all descendants without delete-sharing before removal. It refuses reparse entries, sharing conflicts, depth above32 and more than8192 retained entries. Verified handles are deleted postorder; the retirement marker is the last file removed, after the ownership marker and every ordinary child. Failed cleanup can leave retired files on disk, but startup cannot rediscover their identity. Local cleanup recovery is currently manual. Power-loss durability beyond Windows' successful `FlushFileBuffers` and filesystem guarantees is not claimed.

Legacy data is not copied, moved or deleted. Normal storage remains `%LOCALAPPDATA%/AGI-BROWSE/Profile/Default`; protected Transport storage remains `%LOCALAPPDATA%/AGI-BROWSE/Transport`. `--profile-dir` still means the entire isolated harness root with Default, Profiles and Transport descendants. No data is relabeled Agent and no foreign browser permission import is supported. This Windows implementation does not establish macOS/Linux parity.

The actual ProfileProbe requires renderer cookies, localStorage, CacheStorage, geolocation denial and real HTTP cache isolation in Human, Agent and a native-menu-created profile, then persistence across full host restart. A restrictive Human notification setting must remain absent in the other contexts. Creation uses an actual native profile-button mouse event, root/cursor checks, real Windows menu ownership/foreground readiness and one Home/Enter `SendInput` dispatch. Partial input is never retried. Deletion tests use narrowly verified temporary fixtures; automated native deletion confirmation and formerly CEF-used profile deletion are not claimed by the never-opened fixture.
