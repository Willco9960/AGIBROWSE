# Security policy — AIBROWESE-006

Status: accepted implementation contract, 2026-10-02; coordinator design review passed. Runtime enforcement and attack tests are **planned**, not implemented by this card. [Architecture](../architecture.md), [interfaces](../contracts/interfaces.md) and the unchanged [five-tool manifest](../contracts/agent-tools.reference.json) constrain this design. [Decision vectors](decision-vectors.json) and [design checks](../../tests/security/policy-contract.test.mjs) make its coverage reviewable.

## Principals, assets and assumptions

| Principal / boundary | Trust and protected assets |
|---|---|
| Human → native host UI | Sole approval authority; approve authenticated client identity, exact scopes and sensitive resources in chrome owned by the host, never in a website/modal controlled by a renderer. |
| Website / renderer → host | Hostile text, URLs, scripts, accessibility metadata and renderer messages; protect profile cookies/storage, credentials, files, native APIs and other documents. A compromised renderer must still lack privileged IPC handles. |
| Unpaired local client → broker | Hostile process can probe ports, forge headers/IDs and race/replay messages. Loopback, same OS user, a PID, tool annotations or knowledge of an opaque ID never establish pairing or authorization. |
| Paired client / either model → host | May be buggy or malicious within its identity. Protect other clients, profiles, tabs, frames and operations. Strategies, confidence, local model choices and page instructions are proposals only. |
| Broker → host / host → OS | Broker transports redacted data; host owns grants, engine identity, dispatch and file/secret resolution. Broker is a privileged transport TCB member: compromise can impersonate its active clients within existing grants and disclose cached redacted data, but must not mint/widen grants or resolve native resources itself. |

Protect human control, private observations, session/pairing keys, grant epochs, receipts, resource availability and audit integrity as well as website effects. Host code, native approval UI, OS kernel/credential store and installation integrity are trusted. Administrator/root compromise, debugging/injection into a privileged host/broker, or theft of a client's protected private key defeats the corresponding identity boundary; same-user malware is not universally isolated by a desktop OS. State this limit, while still testing ordinary unpaired same-user clients and sandboxed renderer attacks. A host compromise is not contained by this application policy. Updates/signing remain task 076; task 066 rechecks that boundary before release.

Task 003 already established a pinned Windows sandboxed window with restricted renderer-token/lifecycle evidence in [003 evidence](../evidence/AIBROWESE-003.md). It did **not** establish IPC authorization, paired clients, malicious-page resistance or cross-platform containment. The local HTTP server in [fixture documentation](../../tests/fixtures/README.md) is test infrastructure, not a production broker. No claim here depends on an unverified CEF callback or sandbox capability; 007/019/026 must prove the required interception/enforcement using the pinned build, otherwise the affected operation is unavailable.

## Grants and decisions

Native host stores immutable, closed typed grant records. Required fields: `version=1`, `grant_id`, `client_id`, `session_id`, `profile_id`, nonempty `tab_ids`, nonempty `contexts`, nonempty `operations`, `mode=observe|control`, positive integer `generation`, and `expires_after_ms` (1–28,800,000). IDs are opaque nonempty strings (maximum 128 characters); lists are unique and bounded (32 contexts, 64 tabs, 32 operations). Context is exactly `{kind:"origin", origin:<canonical HTTP(S) origin>, frame:"top"|"same_origin_descendants"}` or `{kind:"host_blank", frame:"top"}`. Unknown fields/types/enumerations, wildcard identifiers/origins and empty scopes fail closed. This is a host-internal policy record, **not** a new public tool schema or a bearer capability. [Examples](decision-vectors.json) contain valid and invalid instances.

`same_origin_descendants` is an explicit native-UI choice for that exact origin within the named tabs, never implicit inheritance. `top` excludes all subframes. Every target is still bound to the host's current frame/document identity. Cross-origin descendants require a separate context for their own exact origin with `same_origin_descendants`; parent permission alone is insufficient. A same-origin embedded document can influence another same-origin document by browser semantics; frame targeting is not a new same-origin security isolation boundary.

`operations` is the closed set `observe`, `wait` and the 19 action types in the manifest: `click`, `hover`, `focus`, `fill`, `fill_secret`, `select`, `set_checked`, `press`, `scroll`, `navigate`, `open_tab`, `back`, `forward`, `reload`, `focus_tab`, `close_tab`, `upload`, `dialog`, `drag`. No arbitrary JS, raw CDP, shell, filesystem-path or approve operation exists. Observe mode permits only `observe`/`wait`; every `act`, including focus/scroll, needs control mode, its exact operation and a current exclusive tab lease. `disconnect` releases only its authenticated session; it requires no content grant. `connect` requests scope but never creates it.

Native approval binds the authenticated client, selected profile/tabs, displayed canonical origins/frame policy, exact operations and duration. Start with isolated `agent` profile, observe mode and **zero grants**; `requested_origins=[]` means none, not all. Listing tabs reveals only currently permitted tab metadata. Pairing and content grants are separate decisions; persisted pairing never restores grants after host restart. Session grants expire on monotonic host time within eight hours and on explicit disconnect/restart; no renewal by a model, queued command or reconnect. A user may approve a shorter duration or revoke immediately. Store only monotonic deadlines in memory; do not extend them on wall-clock changes.

Grant widening always requires a new native decision/generation. Narrowing invalidates the old generation atomically. A host-created `open_tab` may add only the newly created tab to the requesting session's grant, if the UI approved that operation and destination context; it never sweeps in existing/human tabs. The last-tab replacement blank inherits only an already approved host-blank context. Native account/profile selection, pairing, site permissions, certificate exceptions and OS dialogs are not page `dialog` actions. `dialog_ref` identifies only a host-registered website JavaScript dialog in the authorized document; it cannot target approval chrome.

| Decision boundary | Required conjunction / rejection |
|---|---|
| Admission | Paired live identity and bound session; supported closed schema, known operation, bounded payload/queue/deadline. No defaults may widen scope. |
| Read, inventory, wait, replay, receipt lookup | Host-authorized current client/session/profile/tab/context/operation/generation; recheck before delivery, including cached deltas, cursors, events and errors. No cross-client existence oracle. |
| Dispatch | Above plus current observation/document/frame/ref/actionability, exact operation, live control lease and all sensitive-resource approvals. Host derives destination and identity; never trusts client-supplied origin/profile/ref alone. |
| Multiple targets / navigation | Every ref/option/drag endpoint/dialog belongs to the authorized current context; validate source and each resolved destination. Cross-frame drag is unavailable until explicit policy and tests exist. |
| Missing authority | Deny without dispatch. A paired, validly scoped request missing a human-sensitive decision may return `NEEDS_APPROVAL`; invalid identity/scope does not open an approval prompt automatically. |

Evaluation order is transport/authentication → syntax/bounds → session/grant → scope/operation → observation/target → lease → sensitive approval → dispatch. Deny at the first failed stage and disclose only a stable non-sensitive reason. Transport failures close before a tool response. Public error codes remain those in [interfaces](../contracts/interfaces.md); internal reason IDs in the vectors refine them without adding tool inputs. `NEEDS_APPROVAL` is `rejected/not_sent`; after native approval obtain a fresh observation and issue a new request. An old queued request never resumes itself after approval.

## URL, origin and frame policy

Use a browser-compatible URL parser in the host, not a prefix/substring/regex authorization test. Parse once for the decision and dispatch that validated resolved destination; any engine-resolved change is checked again. Raw action inputs must first satisfy the manifest. Authoritative parsing rejects malformed URLs, credentials/userinfo, controls, whitespace repair, backslashes, unsupported schemes and ambiguous/noncanonical numeric IP spellings. Canonical origin equals `(lowercase scheme, canonical ASCII/IDNA host, effective port)`: remove a default port, preserve a nondefault port, reject wildcard/opaque origins. Origin grant input contains no path except `/`, query or fragment; URL action paths/queries/fragments do not create extra authority. Show canonical ASCII host plus Unicode display in native approval to expose lookalikes. Browser/host parser disagreement blocks the operation until fixed.

HTTP and HTTPS are distinct; subdomains, ports and trailing-dot hosts do not silently inherit another grant. `example.com.evil.test`, `example.com@evil.test`, `https://example.com:8443`, HTTP downgrade and Unicode lookalikes cannot match `https://example.com`. Canonicalization does not establish server trust: normal certificate validation still applies; invalid certificates cannot be bypassed through tools. Plain HTTP requires an explicitly displayed HTTP grant; never infer it from HTTPS. Website permission/certificate UI belongs to task 014; agent scope never grants microphone, camera, clipboard, geolocation or a certificate exception.

Host checks navigation destinations before requests for `navigate`/`open_tab`, history/reload, link/form submissions, redirects (every hop, including HTTP 307/308 body preservation), frame navigation and script-triggered navigation caused by an agent action. Ungranted destinations are blocked and authority does not follow them. Source requests already sent may have effects; a blocked redirect is not rollback. If a target cannot be intercepted before network dispatch, report unsupported coverage and hand it to the human. Human-initiated navigation remains possible but suspends agent reads/actions until the new context is granted and observed. Tasks 019/026 must test navigation races and document replacement, not merely inspect the requested URL.

The host-created blank tab is a synthetic **policy context**, not an origin called `null` or `about:blank`. Bind its marker to the actual host-created tab/document; allow inventory/observe, focus/close and approved navigate/open_tab from it. It exposes no website DOM, secret fill or upload. A renderer-created `about:blank`/`srcdoc` uses host-observed effective origin and creator/frame identity, never the synthetic marker. Opaque/sandboxed frames are unavailable for agent read/control in v1. `data:`, `javascript:`, `file:`, `blob:`, browser-internal schemes and external protocol handlers are not accepted navigation destinations. They cannot tunnel through history, redirects, page dialogs or a forged blank marker.

An origin grant controls agent observation/interaction and agent navigation. It is **not** a complete network firewall: an authorized website can issue ordinary subresource/fetch traffic and exfiltrate data already delivered to it. Do not claim origin grants eliminate in-origin malicious behavior, DNS rebinding of websites, or CSRF. Production broker authentication/browser-origin rejection must remain effective even when a malicious website reaches loopback. No credential or local file is released merely because its containing page origin was approved.

## Pairing, transport and IPC constraints

Native UI initiates enrollment; there is no unauthenticated network API that can approve itself or spam approval windows. Use reviewed TLS libraries with TLS 1.3 and mutually authenticated client certificates: per-install server key and per-client private keys in platform-protected storage; host owns the paired-client allowlist and revoke generations. An explicit local enrollment channel outside model/page context delivers a one-use challenge bound to the client public key and server public-key fingerprint. The human confirms those identities in trusted native chrome before host registration/certificate issuance. Challenge lifetime ≤ five minutes; consume atomically, permit at most five failed proofs per challenge, then restart from native UI. No private key in command-line args, URL/query, clipboard automation, logs or model messages. Task 008 selects and pins the library/CSR validation details and tests proof-of-possession and replay; an arbitrary self-signed certificate is not a paired credential.

Clients pin the enrolled server identity and validate the exact endpoint/certificate; broker validates the paired client and revocation state on connection and subsequent requests. Unknown/mismatched/expired identities fail closed, with no TOFU on reconnect, plaintext fallback or disabled certificate validation. Key rotation requires authenticated overlap authorized by the host or fresh local enrollment; losing a key requires re-pairing. No unattended auto-rotation that trusts a new key from an unauthenticated endpoint. Certificate lifetimes/rotation format are task-008 versioned settings subject to this rule; acceptance must include restart/expiry/revocation tests.

Bind explicitly to `127.0.0.1` and/or `::1`; never wildcard interfaces, DNS aliases or public listeners. Reject non-loopback peers and unexpected Host/authority values against the configured literal endpoint. Reject **any** WebSocket `Origin` header, including `null`, before upgrade; absence is not authentication and native clients can forge it. No CORS browser bridge, cookies as credentials or query bearer tokens. Authenticate before protocol/session data is returned. Disable WebSocket compression initially; enforce finite handshake deadlines, frame/message size, nesting, rates, sessions, queue memory and idle lifetime, including unauthenticated connections. Task 008 must publish concrete tested bounds before transport acceptance, while 021 owns state-specific bounds. The existing fixture HTTP service is exempt only as test infrastructure.

Host launches its broker with a dedicated inherited private IPC channel: explicit handle inheritance allowlist on Windows, connected socket pair on POSIX; never a globally discoverable renderer-accessible endpoint or a command-line shared secret. OS access controls plus expected launched peer/process lifetime and startup channel challenge bind the peer; PID or executable name alone is insufficient. No renderer/helper inherits channel endpoints or enrollment/key material. Close unused ends, refuse channel reuse across host generations, stop sessions on channel loss and prohibit handle transfer from message fields. Task 007 proves the platform mechanism and records its OS-specific construction; if peer identity/containment cannot be established, fail startup rather than falling back to an open pipe/socket.

Both IPC endpoints parse closed versioned tagged messages with explicit length/framing and finite depth/string/list budgets; reject unknown tags/fields, duplicate keys, wrong types, overflow, stale generation, replay/out-of-order sequence and sender/destination mismatch. No deserializing executable objects or agent-selected method names. Host binds sessions to the authenticated client registered through its broker channel and checks the current host grant; it never accepts a broker-authored grant. Renderer messages are a separate, unprivileged provenance lane and cannot be upgraded by copying a broker message tag. Each CEF-originated callback must resolve browser/frame identity from the host's live registry, not renderer strings. Privileged DevTools remains host-internal with no externally reachable debug listener. Schema/IPC fuzzing and pinned-build tests are task 007/067 gates.

## Revocation, takeover and delivery timelines

Use one host serialization point per tab for grant generation, document identity, lease epoch and dispatch commitment. Check all immediately before dispatch; release no locks across an unchecked enqueue-to-execute gap. A command may be admitted/queued without authority to execute later. Define dispatch commitment as the earliest handoff after which the engine may cause the effect; record request identity and pending status **before** that handoff. Lost evidence is uncertainty, never evidence of `not_sent`.

| Ordered timeline | Required result |
|---|---|
| Queue A → revoke R → dispatch attempt A | R increments generation, cancels A; receipt `rejected/not_sent`, `PERMISSION_DENIED` / `GRANT_REVOKED`. Subsequent grants cannot revive A. |
| Queue A → native input H → dispatch attempt A | H revokes lease first and cancels all affected undispatched work; `rejected/not_sent`, `CONTROL_REVOKED`. Exclusive lease prevents two agent writers. Human browsing stays responsive. |
| Commit A → R/H → known engine completion | Stop subsequent commands; preserve A's truthful `sent` receipt and known completed/failed result. Revoke does not undo website effects. |
| Commit/handoff A → crash/channel loss before reliable evidence | Preserve/recover `unknown/sent` if handoff is known, otherwise `unknown/unknown`; never claim `not_sent`, success or safe automatic retry. |
| Build/read/cache/event at generation G → R → delivery | Drop pending payloads for G, invalidate observations/cursors/replay/cache/subscriptions and stop subsequent reads. Return only a sanitized revocation/control notice or permitted receipt status. Bytes already handed to a socket/client cannot be recalled. |

Revocation ack is a delivery barrier: broker applies purge/cancellation and acknowledges the new generation before host reports completion; if broker cannot confirm, close its transport/channel and fail closed. Already in-flight bytes may arrive before that barrier, so do not promise physical erasure from clients. Even delayed old-generation events must not be delivered after the barrier. Cache keys include authenticated client/session/profile/tab/context/grant generation/projection identity. Recheck authorization at egress, not only extraction. `wait` and error messages cannot disclose revoked titles, URLs, text or other clients' existence. On a narrowed grant, a fresh observation is required; no silent empty delta.

Human input revokes control leases, not automatically all independently authorized observation grants; native revoke/disconnect revokes the corresponding grants and reads too. Reacquiring control requires a fresh native decision/lease and observation; synthetic page events or agent input cannot impersonate the human takeover/approval channel. On explicit aibrowese_disconnect, credential revocation, profile deletion, host restart, channel trust loss or expiry, cancel undispatched work, invalidate associated refs/leases and purge broker state. Credential revocation affects every session for that client; profile deletion affects all clients for that profile. Human tabs remain open on disconnect.

Request deduplication is scoped to authenticated live session and canonical full request payload. Identical request IDs retrieve existing sanitized status, never redispatch; changed payload with the same ID fails. Revoked callers can receive only their own minimal execution-status tombstone while transport identity remains valid, without page/resource content; unknown status stays unknown. A transient authenticated WSS drop cancels undispatched commands and revokes control leases. Task 021 may retain a bounded existing application session and acknowledged replay history: the same authenticated client may resume only still-valid grants under their original deadline, without extending authority or replaying effects. Reacquire control through the native lease rule; missing history, revision/hash mismatch or a gap requires an authorized fresh snapshot, never an empty delta. Explicit disconnect, host restart, revocation, expiry or channel trust loss invalidates the affected grants; a fresh application session requires native approval. Task 026/021 defines durable receipt/recovery and bounded tombstone retention; eviction never converts an unknown request into a fresh action. Clients must reconcile uncertain effects with a human/fresh allowed evidence instead of generating a replacement ID.

## Files, secrets and publication

Host-only native selection creates unguessable `file_ref`/`secret_ref` entries bound to client/session/profile/tab/document/target, exact destination origin, operation, grant generation, expiry and approved use count (one by default). Sensitive UI shows resource and actual destination; origin/operation grant alone cannot approve a resource. Resolve only **after** scope/lease/target/expiry checks and immediately before dispatch. Revocation invalidates unused refs. Secret source is platform-protected storage; failure does not fall back to plaintext. File selection pins the selected file identity/handle and revalidates against replacement/symlink races; no client paths, arbitrary directory reads or scope from a filename. Tasks 044/050 own platform details and negative vectors.

No resolved value, local path, credentials, raw backend IDs or sensitive form state crosses host→broker publication, diagnostics, recordings or tool errors. Mask password/marked sensitive fields and omit their values, lengths and hashes; redact corresponding names/attributes, old deltas, URLs containing secrets, search snippets, dialog text and reflected known secret values before cache/log serialization. Apply the same allowlist/redaction to receipts, replay, debug exports, telemetry and crash reports. Host crash dumps can contain memory: disable automatic full-memory dumps/exports by default, require explicit native consent and a documented sanitization/retention path before enabling diagnostics. Task 069 must test the actual export path, not just a logger mock.

After an approved fill/upload, the destination website receives the data and can transform, retain or retransmit it. Known-value filtering cannot prove detection of every encoding or derivative; unmarked private page data may remain in permitted observations. Task 010/068 must document this residual exposure and unsupported redaction coverage. Observation permission explicitly discloses that allowed semantic page content can reach the paired external client/models. Default broker observations/events are memory-only, bounded and session-limited; optional recordings require native opt-in and explicit retention. Delete application-managed caches/recordings/refs on expiry/profile deletion; revoke keys and remove managed records, without claiming forensic secure erasure of OS backups, SSDs or clients' copies. Minimal audits contain opaque IDs, reason/outcome and timing only, never content.

## Prompt influence and verification ownership

Page labels, fake system prompts, screenshots, model annotations and local provider output never grant new operations, origins or resources. Host does not parse prose as consent. [Two-tier integration](../contracts/two-tier-agent.md) retains deterministic validation; a model cannot manufacture refs, strategy scope or native approval. Prompt injection can still persuade an agent to misuse **already authorized** clicks, sends or disclosed data. Narrow grants, revocation and native sensitive-resource approval bound that risk; this policy does not promise semantic understanding of every business consequence.

General browser workflows remain the goal. Later paper trading must verify paper account/environment and refuse ambiguous/live transitions; generic strategy/grants confer no real-money trading authority. No added paper position/notional/loss caps are introduced. Platform permissions and finite runtime resources remain mandatory, independently of business strategy.

[Decision vectors](decision-vectors.json) assign stable case IDs, expected decision/reason, concrete fixture and future owner tasks across malicious pages, rogue clients, cross-profile reads/writes and confused deputies. Every row is `planned_runtime`; the passing design checker validates only completeness, closed examples, ownership and links. Task 007 owns application escape/IPC; 008 pairing; 009 scopes/egress revocation; 010 redaction; 015 human priority; 019 frames; 026 dispatch/dedup; 044 files; 050 secrets; 066 independent review; 067 fuzzing; 068 malicious influence; 069 retention/exports. Task 066 must review implemented code/protocols and unresolved critical/high findings block release. Model design/review is not an independent penetration test, runtime attack evidence or M02 acceptance.
