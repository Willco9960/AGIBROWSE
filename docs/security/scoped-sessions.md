# Host-owned scoped sessions — AIBROWESE-009

The host now owns authenticated transport-session scope state and revocation. [Policy](policy.md) remains authoritative. [Evidence](../evidence/AIBROWESE-009.md) separates real TLS/private-channel lifecycle tests from native scope-gate tests. [ADR-003](../decisions/003-host-scoped-session-lifecycle.md) records the lifecycle choice. The five public tools and temporary transport-only `AT01` probe are unchanged.

## Authority and scope

`ScopedAuthority` is a host-only C++ component, never deserialized from IPC or renderer messages. Binding an authenticated identity creates **zero grants**. A native grant is copied into an immutable record containing version, grant/client/session/profile IDs, exact tab IDs, contexts, closed operations, mode, increasing generation, and monotonic duration. IDs use the existing bounded opaque-ID rules. Tabs are unique/nonempty/at most64, contexts32, operations21 (the entire closed operation set); duration is1–28,800,000ms. An invalid replacement cannot invalidate or widen the current grant. A valid replacement atomically invalidates its predecessor's tickets and leases.

The host must supply a trusted browser-parser predicate accepting only already canonical HTTP(S) origins. The scope gate performs exact equality against registered native document origins, never string-prefix URL parsing. Production currently supplies a rejecting predicate because native grant UI/browser-origin extraction is not enabled. Tests use an explicitly closed origin oracle; they prove exact scope comparisons and rejection of invalid oracle inputs, **not** a production URL parser or navigation interception. Those engine gates remain019/026. Host-blank context is separately typed, native-created/top-only, with no origin and no DOM action access. Renderer blank/srcdoc/opaque provenance cannot enter this registry through the current renderer lane.

Documents are registered only by trusted native code as `(profile,tab,frame)` tuple keys with exact document identity, origin/context and top-frame status. Up to256 documents are stored. Same-origin descendants require an explicit frame policy. A cross-origin descendant needs its own exact context with descendant policy; a parent grant supplies no inheritance. Registration/replacement increments a native revision; removal and recreation cannot revive an admitted ticket.

Observe/wait require exact client/session/profile/tab/context/operation coverage. Every closed action needs control mode, its own exact operation, and an exclusive lease for the profile/tab. Leases belong to one session and carry a native revision; release/reacquisition invalidates old action tickets. Expired/disconnected/revoked owners cannot retain a lease. Target/actionability, sensitive-resource approval, navigation destinations and actual engine dispatch are still separate mandatory checks before any future adapter can operate.

## Bounded synchronous delivery gate

`QueueScopeCheck` admits at most128 native tickets. Each captures the request, grant generation, document revision and control-lease revision. Ticket IDs increase monotonically and are never reused; counter exhaustion fails closed. `WithCurrentScope(ticket,handoff)` consumes a ticket once even on rejection or exception. It samples the injected trusted monotonic clock **inside the mutex immediately before the actual synchronous handoff**, then repeats all scope/identity/document/lease checks. It does not accept a caller-supplied cached dispatch timestamp. The same gate is required for command handoff and every observation or content-bearing metadata/cache/event/error delivery. The existing non-content `AT01` response remains generic `PERMISSION_DENIED` without a content grant.

The callback must be bounded, synchronous and nonreentrant. It must perform the actual handoff before returning; scheduling an unchecked later task would break the contract. Clock/origin callbacks are also trusted and nonreentrant. All changes serialize with the handoff: an already entered handoff finishes before a concurrent revocation returns; later handoffs are denied. `/EHsc` is explicit for the MSVC library/consumers so throwing native callbacks release the mutex. A callback exception never proves the absence of an effect; future026 outcome handling must preserve unknown effects and prohibit automatic replay.

## Authenticated host lifecycle

`HostTransportAuthority` owns one scope authority. The broker creates fresh random64-hex transport IDs, and the host binds them only inside an atomic pairing callback that validates the live issued certificate and credential generation. The native pairing mutex serializes validation/binding against native revoke. Lock order is pairing → host binding → scope; scope callbacks never call pairing or reenter host state. Existing bindings retain the exact client, certificate hash, credential generation and original deadline. Rechecks cannot renew them; the **same original host deadline** is passed into the scope binding.

This integration supports task008's temporary60-second transport sessions. It deliberately supports no resumed application grant after a socket drop: reconnect binds a fresh session at zero authority. Policy006's later application-session/replay semantics and eight-hour maximum grant duration remain unchanged; durable/resumable public application sessions belong to021/031. Effective authority expires at the earliest grant or original transport deadline, even when the requested grant duration is longer.

There are at most64 live bindings and4096 total live/tombstone entries. Disconnected/revoked bindings remain tombstones until their original transport deadline; expired scope entries are pruned on admission. Host binding tombstones additionally retain a10-second grace period to recognize an already-expired socket's delayed close. Known exact duplicate/expired closes are idempotent and never restore authority. Admission fails closed at the finite ledger bound; it does not impose a64-connections-ever lifetime limit. The current listener admits at most64 attempts/s,8 concurrent sockets; these bounds are unchanged. A close arriving after its tombstone/grace was pruned is an unknown private-peer assertion and closes that channel.

Native pairing revocation has weak lifetime-safe listeners for every live host authority (at most64 registrations, expired listeners pruned). Each affected session is tombstoned, its tickets/leases/grant removed, before persistence begins. A throwing listener cannot skip later listeners or retain the paired runtime credential; its failure propagates after durable deletion when possible, causing the native UI to stop transport. Failed marker writes also remove the runtime credential and revoke scope. If the OS refuses persistence, the former disk pairing may still exist: local recovery/re-pairing is required before transport restart. A successful pending marker followed by a failed vault save still prevents restart resurrection, as008 tests establish. No application grant is persisted in either case.

Host channel shutdown invalidates scope **before** joining/stopping pipes. Malformed private messages, identity callback/crypto failures, unexpected close bindings, broker death and channel trust loss invalidate all session authority and terminate the exact launched broker. The native host keeps human browsing available. Client certificate revocation is rechecked by the real broker within the unchanged250ms timer plus bounded private exchange.

## Private IPCv2 close message

The coordinator approved one new internal kind, `10=session_closed`. Its exact tag set is `{1,2,3,5,6,14}`: version2, kind10, next positive identity sequence, client ID, session ID, channel epoch. Length is at most2,048bytes. Unknown/duplicate/missing/type/version/length errors reject. No certificate, origin, grant, operation, page data or public schema field is added. Version1 cannot carry this message.

Only a socket with a successful host identity binding emits the close callback. The broker serializes close and identity exchanges under the same mutex/sequence. Close is **one-way**: the host sends no acknowledgment that could be stranded in the next identity response. A wrong client/session/epoch, replay/out-of-order sequence or malformed message closes the private peer. Writes use the existing500ms deadline/1,000ms cancellation bound. A failed close write stops broker transport; host channel loss supplies final invalidation. The authenticated host binding check, not a client-provided ID alone, determines the affected scope.

## Current production limit

Production installs no scoped grants, registers no engine documents, and enables no application observations/actions. Existing IPCv1 intents still hit task007's zero-grant admission fixture; they cannot create grants. Future021/026 integration must use this scope gate at actual dispatch and delivery instead of treating the old minimal `Boundary` fixture as complete authority. No new native grant UI, arbitrary JavaScript, CDP, renderer entry, public connect schema, stream cache or engine action is implemented by009. Native confirmation remains the sole grant source; the existing keyboard callback does not prove physical human input. Future dispatch must exclude privileged `Ctrl+Shift+P/I/R` regardless of event provenance.
