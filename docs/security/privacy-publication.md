# Host privacy publication boundary — AIBROWESE-010

[Policy006](policy.md) remains authoritative. This implementation covers the current fixed host diagnostics, CEF nonfatal console fallback and disabled diagnostic destinations. Application observations/actions, semantic extraction, frame-sensitive classification, stream/cache/delta/replay/receipt exports are not enabled by this task. Production still creates no application grants or engine document registry, and the authenticated broker's sole temporary `AT01` response remains exactly binary `PERMISSION_DENIED`.

## Current enforced exports

Every browser `Record` call uses `agi::privacy::Event` and `WriteDiagnostic`; there is no free-form event/message parameter. The closed event names retain the existing `{event,value}` lifecycle schema. Numeric values are zero except actual native process/browser/window identities and bounded HTTP statuses (0 or100–599). Host call sites derive IDs/statuses from native/engine APIs, never renderer payloads; unknown events or invalid values produce no record. Console message, source URL, line number, title, error text, failed URL, dialogs, renderer payload strings, form state, lengths and hashes cannot be serialized by this interface. It is not permission to encode content in a numeric ID.

`OnConsoleMessage` returns true and omits the entire message/source/line before CEF's fallback output. At most one fixed console-suppression event is emitted per browser. Human window titles still use the actual title; human page UI/dialogs and DevTools browsing remain human surfaces, not agent publication. No arbitrary JS/CDP public API is introduced. The private host→broker transport configuration carrying the server leaf key is privileged trusted setup, not page/agent publication or a content cache.

Browser command-line feature configuration is disabled with `command_line_args_disabled`; application arguments are read into host state before CEF resets its command line. `LOGSEVERITY_DISABLE` sets CEF's minimum log level to FATAL. Browser-only `OnBeforeCommandLineProcessing` also appends Chromium `disable-logging`, disabling the independent Chrome destination before it creates a file/inherited log handle. Startup rejects logging/file/netlog/trace/crash override switches before `CefExecuteProcess`. Core sandbox/CDP switch rejections remain active in all processes. The sole diagnostic child exception is the exact generated `log-severity=disable`; `enable-logging` and `log-file` are never broadly allowed for a user-supplied `type`.

The source basis is the exact pinned [CEF chrome_main_delegate_cef.cc](https://github.com/chromiumembedded/cef/blob/a03e7146331fc5bd72784591e82df01e8007e17b/libcef/common/chrome/chrome_main_delegate_cef.cc), [CEF child switch forwarding](https://github.com/chromiumembedded/cef/blob/a03e7146331fc5bd72784591e82df01e8007e17b/libcef/browser/chrome/chrome_content_browser_client_cef.cc), Chromium154.0.8037.94 [GetLoggingDest](https://github.com/chromium/chromium/blob/154.0.8037.94/chrome/common/logging_chrome.cc) and [PassLoggingSwitches](https://github.com/chromium/chromium/blob/154.0.8037.94/content/browser/child_process_launcher_helper_win.cc). CEF severity changes and Chromium file destinations are separate; inherited logging handles are generated when a file destination remains active. The exact rejected child command was not captured locally, so the initial GPU-failure diagnosis remains source-based; corrected startup, sandbox and shutdown are now verified on exact-source clean Windows CI37135197435.

## Native staging redaction contract

`DraftState` is a native flat field staging contract, **not** an IPC/public schema or a DOM/accessibility extractor. It accepts only printable ASCII, at most128 unique nonempty field names,32 explicit known secrets,4,096 bytes per string and65,536 aggregate input/output bytes. Empty explicit known secrets, duplicate names, unknown field kinds, control/non-ASCII bytes and excess budgets reject the entire state with no payload. Temporary ASCII rejection is a fail-closed integration gate, not the eventual international-browser specification.

Password and explicitly marked-sensitive fields are omitted entirely. Their names/values and native resolved known secrets seed exact substring reflection matching across all remaining text names/values; any match drops the complete field. No mask length, value hash, sensitive name, old value or related attributes are serialized. `RedactedState` has a private constructor and no raw setter; only successful `Redact` creates it, and `Deliver` exposes sanitized JSON synchronously to a native sink. It supplies **privacy only**, never scope authorization. Production has no state publisher yet, so these checks are native contract evidence, not actual semantic export coverage.

Future016/019/021/031 adapters must classify using trusted current engine state, propagate password/explicit-sensitive classification through nodes and associated names/attributes/subtrees, feed resolved secrets from native resource handling, and fail closed for unrepresentable state. They must implement reviewed structured schemas/UTF-8 handling and engine fixtures before those channels can publish. Every actual host→broker/cache/error/event/receipt/delta/replay/recording handoff must accept sanitized state and occur synchronously inside task009 `ScopedAuthority::WithCurrentScope`; raw draft input must never reach those serializers. Reclassify/redact before cache insertion and revision delivery, including old deltas and reflected title/URL/dialog/snippet values. No future extractor is entitled to assume this flat contract proves inherited marking, frame identity, revocation or replay correctness.

Its exact owned temporary credential directory is checked before recursive cleanup and removed on success/exception.

The exact-source clean Windows CI passed this GUI harness, its five startup cases and independent artifact inspection; see [evidence](../evidence/AIBROWESE-010.md).

CEF's documented FATAL stderr exception remains; crash/fatal payloads, OS dumps, Crashpad/third-party diagnostics, human screenshots, profile HTML/cache and forensic erasure are not proven sanitized here.
